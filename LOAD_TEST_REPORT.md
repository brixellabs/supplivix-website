## 2. Concurrency Architecture & Neon Connection Pooling

1. **Atomic Inventory Reservation**:
   - Implemented via `select_for_update()` inside database transactions (`transaction.atomic`).
   - Ensures row-level locking when deducting available stock.
   - When inventory is depleted, subsequent checkout requests are rejected cleanly with human-readable error messages without partial commits or orphaned records.

2. **Neon Serverless PostgreSQL Compatibility**:
   - Configured with `dj-database-url` in `backend/config/settings.py`.
   - **Pooled Connections**: Uses `conn_max_age=0` when connecting to Neon's PgBouncer pooler endpoint (`-pooler`), preventing stale socket errors during serverless compute scaling and scale-to-zero wakeups.
   - **Direct Connections**: Migrations automatically route through `DIRECT_DATABASE_URL` to bypass transaction-pooling limitations on DDL statements.
   - **Connection Health Checks**: `CONN_HEALTH_CHECKS=True` automatically verifies connection liveness before executing queries.
   - **Wake-up Retry Protocol**: The `/api/health/` endpoint incorporates Neon compute wake-up detection and retry logic.
